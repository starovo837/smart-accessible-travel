# Windows 桌面入口

双击本目录的 `install.vbs` 创建“智能无碍行”桌面快捷方式。双击快捷方式即可启动本地服务，并在 Edge 或 Chrome 独立窗口中打开。

这是当前网页原型的桌面启动方式。它使用项目的 `dist` 构建文件和已有 Node.js 运行环境；请保留项目文件夹。电脑重启后，双击图标会自动启动服务。退出窗口不会删除浏览器中已授权保存的资料。

应用仍使用 `http://127.0.0.1:5173/`，因此同一浏览器在该地址保存的资料可以继续使用。已有 Vite 服务运行时会复用该地址。修改软件后，在项目目录运行 `pnpm build` 更新桌面版本。

取消桌面入口：删除桌面“智能无碍行”快捷方式即可，不会删除项目或用户资料。启动失败时查看本目录的 `desktop.log`。

当前本地服务监听 `0.0.0.0:5173`，支持同一局域网访问。电脑需要保持开机、服务运行。

要让同一 Wi-Fi 下的手机访问，先双击 `allow-lan-firewall.cmd` 并在 Windows 管理员提示中选择“是”。然后在电脑运行 `ipconfig`，找到 WLAN 的 IPv4 地址，在手机打开 `http://电脑IPv4地址:5173/`。电脑 IP 可能随 Wi-Fi 变化。

## 商品资料解读

“买辅具”现在以资料解读为主入口，接受商品文字、商家回复、用户反馈及 PNG/JPEG/WebP 图片。购物平台搜索保留在页面下方。商品链接不会自动抓取，须提供对应文字或图片。

预置案例与规则整理不调用模型；规则整理只识别有限格式，三维尺寸需明确标注长×宽×高。真实 AI 使用电脑上的 Ollama + Qwen3-VL 4B Instruct 图文模型，支持文字及图片。固定使用 `qwen3-vl:4b-instruct`，避免默认长思考版本消耗提取额度。商品AI接口不使用 `.env.local` 中的旧密钥，也不会回退到云端服务。Node.js 需支持原生 TypeScript（当前使用捆绑的 Node 24）。

电脑首次使用：双击 `install-local-ai.cmd`，下载官方 Ollama 便携版及本地图文模型。下载中断可以再次运行以继续下载。运行环境与模型位于项目 `.local-ai/`，不会进入版本控制。安装脚本固定官方版本并校验 SHA256，不修改防火墙或系统启动项。模型首次安装需要互联网，之后处理资料无需互联网；首次加载、CPU回退或电脑繁忙时可能较慢。

打开“买辅具”会自动尝试启动已安装的引擎。选择“本机AI解读（无需密钥）”，加入文字或图片，再点“开始本机AI解读”。每次最多5份资料，其中最多2张图片（每张3MB），文字合计6000字；长资料分批提供关键页。结果未完成时不会替换为固定答案，可取消并保留原资料重试。

模型引擎仅监听 `127.0.0.1:11434`，设置 `OLLAMA_NO_CLOUD=1` 禁用云端功能。手机通过软件同端口的代理访问电脑，不需要向局域网开放模型端口。手机首次调用需在电脑“手机首次授权 / 模型状态”中生成一次性授权码，10分钟内在手机输入。浏览器授权有效12小时；重启软件服务后需重新授权。电脑需要保持开机且与手机处于同一网络。此授权码不是云服务API密钥。

结果区分原文引用、图片识别、未找到原文、资料冲突和本人核对。反馈按使用问题归类，不代表全部用户评价。只有本人核对的参数才进入出行计算；不含电池的重量不会直接作为整机运输重量。原图和完整原文不写入长期商品对比存储。

自动测试覆盖来源校验、本机服务限制、云模型拦截、缺模型/不完整输出、引用与参数确认。可手动运行 `node scripts/smoke-ai.mjs`，仅向本机发送合成轮椅文字进行真实模型检查，不读取用户资料。小模型输出仍可能出错，引用、型号、单位和真实操作需要人工核对；屏幕阅读器与残障用户实测需另行安排。

## 完整资料核验与协作

- 商品解读会逐项检查数值、单位、尺寸顺序、使用／折叠状态及型号。错误引用不参加计算；不同型号单独选择，同一资料混有多型号而引用未标明型号时要求拆分资料。
- 图片先生成逐行文字，再提取参数。转写仍是AI结果，不构成独立证据。用户可用另行取得的厂家文字、本人测量或本人授权协助者的记录复核，之后才确认设备参数。
- 在商品、出行结果页选择“围绕这份资料／这次出行问AI助手”，可让本地模型根据列出的当前依据解释，回答附对应引用。固定流程助手仍单独标示。输入方式与朗读偏好独立选择，不按障碍身份强制关闭语音。
- 出行页面的“更新官方来源与版本”实际访问预设官方页面，不发送个人资料。每条规则显示适用范围、版本、生效日、核验日和七天复核期限。来源内容变化、无法读取或超过复核期限时，不套用原来的数值限制。当前接入中国铁路国内携带品、国航辅助设备和轮椅电池条款；不冒充覆盖其他航空公司或各城市线路。核验公开文本不等于核验本次航班、机型或获得运输许可。
- 纠错可主动提交到当前服务，在“我的 → 纠错记录与处理进度”追踪。服务端最长保留30天，可提前删除。在运行服务的电脑使用 localhost 进入“纠错处理工作台”核查、回复、记录依据和修正版本；来源全文变化也须在工作台复核，关键片段不匹配时不能强行通过。
- 家属分享按所选范围保存到当前服务，链接有效期可选1／3／7天，可撤销或删除；家属只提交进度建议，由本人确认才采用。点击“同步我当前的资料与进度”发布最新状态，查看页每15秒更新。不会发送实际消息，也没有公网跨网络同步服务。电脑生成的链接优先使用可用局域网地址，仍须同网络、电脑服务运行与防火墙允许。
- 纠错与分享的查看／管理凭据不同。凭据按生活资料保存授权保留；不授权保存时刷新会丢失，先在“我的 → 纠错记录”下载本人管理凭据，日后可在同一服务导入。管理文件不要交给家属。服务端保存使用本机文件加密；不等于端到端加密或生产级多账号隔离。不能直接把本地审核工作台作为公共运营后台。
- 删除资料会先删除关联服务端副本；若服务无法连接，保留管理凭据并提示重试，不会错误报告全部删除。已导出的文件需自行删除。

## 手机独立使用

“我的 → 离线随身包”可下载两类文件：静态资料包，以及完整的独立应用HTML。构建会生成 `dist/offline-app.html`；完整应用文件可在支持本地HTML的手机浏览器中打开，设备卡、基础流程、资料案例、已导出的清单不依赖电脑。文件内资料默认只在本次运行使用，不自动授权持久保存。实时规则更新、纠错与家属协作仍需服务。部分手机文件管理器禁止运行HTML脚本，须选择允许本地网页的浏览器。

“买辅具”新增“这台手机／浏览器独立AI（文字）”。使用 WebLLM 的 Qwen2.5 0.5B 文字模型，首次点击才下载数百MB权重；要求可信HTTPS或电脑localhost、WebGPU、足够内存。一次最多3500字，不支持图片；加载后在本设备推理，不用API密钥。普通局域网HTTP及独立file页面不启用该模式。可在商品页单独清理浏览器模型缓存；应用代码缓存与模型缓存分别管理。当前没有自动下载此模型，也未完成手机硬件兼容实测。

正式跨网络使用需要将前端部署到可信HTTPS地址，并另行设计生产后端、身份与权限。只部署 `dist` 静态文件可提供本设备文字AI和基础功能，不能提供电脑图文AI、纠错处理或实时家属服务。安装入口位于离线随身包中；不支持安装的浏览器提供手动说明。此项目尚未公开部署。

无障碍手工验收步骤见 [TESTING.md](./TESTING.md)。自动测试用 `pnpm test`，完整构建用 `pnpm build`。

## 进一步的可靠性与操作改进

商品页的默认流程现在是直接粘贴文字或上传图片，再点“开始解读”。文字来源和型号自动判断，判断错误时可修改。多份资料、手机配对和手动选择引擎在展开项中，不要求首次使用者先理解模型配置。购物平台搜索仍保留在下方。不会自动抓取商品链接。

商品草稿在当前运行中跨页面保留，可导出含原图、全文的草稿JSON，也可重新导入；不把全文或原图偷偷写入长期浏览器档案。导出文件请本人保管，刷新之前应导出需要保留的草稿。来源自动判断不是来源真实性认证。

助手的真实本地模型现在只选择相关依据ID及一个现成的缺项问题，最终答案由程序组合原文、计算结果和状态。模型不能自由改写大小关系、否定词、运输许可或补出新阈值；已发现的不适配与资料冲突会强制出现在回答中。浏览器还会重新按当前依据组合服务返回的选择，忽略服务响应里的自由正文。商品参数提取仍由真实图文AI完成，提取后继续执行单位、引用与型号校验。此约束不能证明商家资料真实，也不能代替实际测量或专业适配。

从首页进入助手会接续当前运行中最近完成的商品或出行检查；页面标明当前资料，可改选其他资料或只用流程引导。多设备可以选择单台。单次最多30条、6000字的容量限制现在明确列出未纳入的条目，关键结论无法全部纳入时会阻止提问并要求缩小范围，不静默遗漏第四台设备。切换资料会取消旧请求并重新确认处理范围。

出行查询在填写前显示实际接入的规则范围。结果分为“已满足所核验条件”“需办理协助”“信息不足，先补充”“当前参数不适配”，附核验边界与明确缺项。“已满足”只用于已知无电池小型辅具的指定铁路普通携带品条件，不代表获得本次行程许可。飞机轮椅客舱尺寸不满足时会提示办理托运，不把客舱存放上限误当作全部运输禁限。

商品结果按设备类别显示日常操作检查：视障设备的辨识与耗材、助听设备的提醒和连接、沟通设备的断网备用、移动辅具的握持与制动、医疗设备的操作与维护资料。保留资料中的“不支持”等否定词，没有找到说明时显示待补充；用户可选择自己重视的问题并复制补问。小型设备不强制填写轮椅式的门宽和折叠表单，分类检查位于“对我有什么影响”。一般操作说明不构成医疗参数调整或临床适配建议。

“我的”只保留设备、生活工具、离线资料、纠错进度和隐私等日常入口，已移除评审模式、开发工作台、测评页面及试用记录工具。手机运行条件检查继续帮助用户判断服务连接和本机AI是否可用。

运行 `node scripts/smoke-assistant.mjs` 可用真实本地模型复测“设备宽68cm、门宽65cm”的受约束问答。它只发送合成资料，不读取用户记录、密钥或云端服务。真实手机兼容、读屏与参与者验收，以及公网部署，仍应按实际环境单独完成。

规则/AI对照脚本、已有测评数据与试用方案仅作为仓库中的开发资料保留，不展示或打包到日常软件。开发复核方法见 [EVALUATION.md](EVALUATION.md)。

## 日常操作减负

商品默认先显示一项关键风险及对应核对按钮，第二项提醒随后显示；其余提醒和全部参数可展开。依据页一次核对一个冲突或参数，勾选后保留确认状态，再点继续。图片独立复核、型号隔离和逐项确认规则保持有效，不提供批量自动确认。

助手默认围绕当前资料自动选择可用的本地AI，处理范围仅需一次明确确认。回答方式、完整依据和模拟识别入口收进“资料范围与回答设置”。优先复用已加载的设备模型或就绪的电脑服务；首次设备模型下载必须单独确认。无服务时保留问题，不把流程引导冒充真实AI回答；仍由程序组合已校验依据，不允许模型改写数值关系。

出行查询固定分为交通方式、设备、参数三步。按方式与设备只询问相关缺项，一次一项，已有参数复用；跳过会保留未知。全部参数与运营方空间可展开编辑，是否写入设备卡仍由本人确认。结果优先给出一项操作：不适配时联系承运方；个人参数缺失时返回补充；仅缺适用规则时准备联系运营方；条件满足时生成清单。原文、全部缺项、后续操作、沟通卡、分享与离线功能均可展开使用，未增加新的规则阈值或许可判断。
