# 会话与限流 D 批

2026-11-18。`server/request-sessions.mjs` 管理会话和限流，`server/product-api.mjs` 在状态查询及原有授权入口调用。`server/studio-policy.mjs` 读取可选的可信代理地址。商品资料页使用文案字典展示状态接口的限流提示。

- 状态查询优先使用有效的 `X-Sai-Session`，然后检查同名 Cookie。过期的请求头或旧路径 Cookie 不遮住另一份有效凭据。连续复用不会重新签发，也不会消耗签发额度。
- 每个 IP 在一分钟窗口内最多申请 6 次新会话，同时最多持有 6 个尚未使用的会话及 64 个会话总计。会话首次成功用于业务后，按最初签发算满 12 小时。未使用会话 5 分钟后失效。商品解读提交前会查询会话状态，长时间编辑后也能在上传资料前处理会话过期或限流。
- 全部会话最多 2,000 个。全局至多保留 500 个未使用会话，达到上限时给新访客腾出最早的未使用会话。已使用会话保留到期。若 2,000 个均已使用，申请返回 429，并按最早到期时间提供 `Retry-After`。有效会话仍可查询状态。
- 业务额度沿用各接口原有上限和响应，计数键固定为 IP 加操作类型。会话和每次处理同意、限时求助能力凭据、异步任务所有权仍各自检查。签发超限使用 429 与秒数形式的 `Retry-After`。Agent Reach 查阅了 [RFC 6585 第 4 节](https://www.rfc-editor.org/rfc/rfc6585.html#section-4)。
- Cookie 使用 `HttpOnly`、`SameSite=Strict`、`Path=/`。直接 TLS、可信代理声明 HTTPS 或仅配置 HTTPS 公开来源的创空间会增加 `Secure`。本机普通 HTTP 继续可用。

## 代理部署

默认使用 TCP 对端 IP。若所有请求都由一个网关转发，会共用同一个额度。只有在核实网关会覆盖或追加可信的 `X-Forwarded-For`、且后端入口受控后，才配置逗号分隔的 `SAI_TRUSTED_PROXY_IPS`。后端从最接近本机的已配置代理向外识别第一个客户端地址。无效头回退到 TCP 对端。该配置不改变来源校验或本机配对权限。魔搭实际代理地址和转发契约尚未实测，本轮尚未发布或写入平台配置。
