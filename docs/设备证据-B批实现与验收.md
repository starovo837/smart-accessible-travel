# 设备证据整改 B 批

日期：2026-11-18。用户已确认开始B批，仅修设备证据进入出行判定的路径。保持A–E五段、依据链接/电话、完成度、本地保存与删除入口。没有新增依赖、付费API、登录或上传；C–E不在本批。

## 数据与规则

- `TravelDeviceSpecs`增加逐字段`confirmed`、`sampleFields`，字段为长、宽、高、重量、折叠状态、电池类型、Wh、数量、可拆卸。确认只接受严格布尔true，有效数值仍须有限且大于0。
- `FieldEvidence.sample`与`Device.sample`保留样例来源；同时识别旧“预置示例”和“模拟识别”来源说明。新样例和旧样例即使留有confirmed=true，也不能被升级为实物证据。
- `storedDeviceSpecs()`保持扁平字段接口，同时返回confirmed映射。普通未核对值只供表单回填；无证据的旧manual描述不再自动确认。折后尺寸须逐项确认，并且折叠状态也已确认且一致。
- `travelSpecEvidence.ts`集中转换、校验、确认与样例排除；`travelRules`和`travelTripIdentity`分别在阈值比较与清单/话术入口过滤。33×91×106、160/300Wh、重量、折叠比较都只能读取过滤后的值。原始描述不再用于推断电池类型。
- `travelCompleteness`的虚构容量探针只计潜在条数，不进入实际设备、正文、导出或携带卡。其合成证据与真实设备来源分离，不能作为已确认的实物资料。

## 交互与保存

- 设备草稿带出后标“待核对”，单击“去核对”可逐项确认。不重复录入已有普通资料。确认后原地重算，并给role=status提示，焦点转到下一项。
- 保留一次一个问题；输入或选择不自动确认，需按确认按钮。修改一项就撤下该项确认，其余不受影响。无效值仍走原有错误提示，不参与判断。
- 缺项表单与高级编辑使用相同确认规则；存回设备卡保留实际确认状态，不把“保存”解释成“全部核对”。新增折叠状态字段仅描述实际运输状态，不计算三维几何。
- 商品样例的事实确认控件禁用，独立图片复核也不接受样例。存卡保留sample标记；助手证据与设备比较也不能把旧样例复选状态称为本人已核对。模拟铭牌为样例，需另建实际设备，不能把模拟数值直接勾选为真实。
- 旧快照无确认信息或保存的结论与确认状态不一致时，恢复前重算，清除原勾选与比较记录。普通草稿留存并提醒重新核对，样例值移除。保留未核验的官方入口，不凭迁移批准规则。
- 快照增加specEvidenceVersion；草稿变更即写本地，哪怕清单未变也能刷新恢复。导出与随身卡只取过滤后的清单设备资料。设备授权与其他隐私行为沿用原规则，分类授权漏洞留给C批，不在此宣称已修。
