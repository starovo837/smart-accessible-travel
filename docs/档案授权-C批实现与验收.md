# 个人档案授权整改 C 批

日期：2026-11-18。用户批准C批，仅处理类别、等级等分类档案的本地保存及清除。不新增依赖、后端或登录；D批会话限流、E1–E10、三维几何与买辅具AI超时不在范围内。

## 文件与数据边界

- `src/app/storage.ts`：统一独立档案键、严格授权条件、恢复、保存及清除。只有`consent === 'granted'`且`privacy.profile === true`允许存；主快照modules也同时检查总授权。恢复失败返回空档案与独立错误，不读取未授权的旧类别。
- `src/App.tsx`：先恢复有效的主授权，再读取分类档案；编辑、授权、暂不填写、撤回、删除统一走存储检查。档案错误不会被普通保存成功提示覆盖。清除确认成功后才清空类别/等级、推荐模块、旧计划比较、相关助手状态与界面选择。
- `src/app/travelTaskStorage.ts`：读写默认不保存档案，调用方必须显式提供当前档案授权。无授权时重新构建普通清单，移除类别、等级、组合建议、旧比较记录及含档案的inputKey，不是只隐藏标签。保留普通行程和已核对设备；分类建议的旧勾选不再有效。历史顶层档案字段也移除。
- `src/app/copyDictionary.ts`：新增可读英文键，提示读取、保存、启动清除及撤回清除失败，显示在现有role=alert区域。
- 新增`tests/profile-consent.test.mjs`；旧逻辑与便携导出测试只更新临时编译依赖清单。README、部署说明、续做记录及上传白名单同步更新。

## 实际行为

1. 未授权或暂不填写：选择在当前运行的内存中生效，不写类别和等级。启动会移除`smart-accessible-disability-v1`的遗留值；未授权时不会从该值恢复选择。过期的主授权也不允许恢复。
2. 已授权且开启档案保存：保存规范化的类别、等级、陪同及主要辅具引用；未知字段（如证件号码）不进入档案。刷新可以恢复。
3. 出行缓存：即便临时使用分类生成了组合清单，写盘仍保存无分类的版本。开启档案保存后才允许持久化个性化建议。清理时使用本地未核验官方入口重建；在线页面仍跟随当前读取的条款记录，不因清理而批准规则。
4. 撤回或删除：同步清理独立键、主快照分类、分类建议缓存与内存选择；单独撤回个人档案不删除设备与生活记录。全部删除沿用原范围，同时清除主存储和出行缓存，不在失败后假装完成。
5. 重新授权：保存当前空选择或本人重新填写的选择，不重新读回已撤回类别。

本地跨多个键不具备事务原子性。失败时可能已有部分键清掉；授权状态与删除对话框仍保留，提示重试，不把已清掉的敏感内容写回作“回滚”。未授权的残留值不加载到界面。新授权也必须先清理残留，清理失败就不切换。
